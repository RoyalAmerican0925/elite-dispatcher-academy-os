# Module 01–06 Exam Blueprint

**Prepared by:** Claude
**Date:** 2026-08-19
**Status:** DRAFT_COMPLETE — framework only; no exam items written yet
**Purpose:** Defines the objective-to-item structure for module-level graded exams, distinct from the diagnostic Knowledge Checks already extracted to `03-ASSESSMENTS/Module-Quizzes/`. Per ChatGPT's 2026-08-19 handoff note, this blueprint must exist before any exam question is authored, and exam items must not simply duplicate the 20-question Knowledge Checks.

## How this blueprint works

For each module, this file defines:
1. Objectives/competencies to be tested (drawn from each module's own "Completion" summary in the student manual, not invented).
2. Cognitive level and item type mix.
3. Number of items per objective.
4. Scenario/practical coverage requirement.
5. Critical-failure content (a wrong answer here should block passing regardless of overall score).
6. Passing standard and remediation linkage.
7. Date-sensitive items requiring source verification before publication.

This is a planning framework, not the exam itself. Actual item-writing is a separate, later task per module.

## Module 01 — Trucking Industry Foundations

**Objectives tested** (from Module 01 Completion): distinguish broker / carrier / dispatcher / driver roles; distinguish USDOT number from operating authority (MC/FF/MX); identify the carrier-side dispatch model; describe the factoring company's function; use DOT/FMCSA relationship correctly; identify consignee/shipper/receiver roles in a scenario.

| Element | Specification |
|---|---|
| Item types | Multiple choice (definitional), scenario identification |
| Cognitive level | Mostly recall/comprehension — this is a foundational module |
| Items per objective | 3–4 |
| Total target | 20–25 items |
| Scenario/practical coverage | 1–2 short scenarios (e.g., extend the Northgate Produce pattern already used in the Knowledge Check) |
| Critical-failure content | None — this module has no regulatory or safety-critical content; a low score should route to remediation, not disqualification |
| Passing standard | Suggest 80% — foundational vocabulary should be solid before Module 02 |
| Date-sensitive items | None identified — this module's content (role definitions, terminology) is not tied to a current-date regulatory figure |

## Module 02 — Dispatcher Role & Legal Boundaries

**Objectives tested:** apply the federal broker definition; apply the bona fide agent exclusion (49 CFR § 371.2(b)); recognize "allocation of traffic"; evaluate multi-carrier representation fact patterns; apply the freight-funds-handling factor; evaluate written-agreement vs. actual-conduct fact patterns; apply current broker financial-security figures; classify scenarios by brokerage risk.

| Element | Specification |
|---|---|
| Item types | Multiple choice, true/false with justification, scenario classification (A/B/C risk tiers as in the Knowledge Check) |
| Cognitive level | Application and analysis — this module is reasoning-heavy, not recall-heavy |
| Items per objective | 3–4, with scenario classification weighted higher since this is the module's core skill |
| Total target | 25–30 items |
| Scenario/practical coverage | At least 6–8 scenario-classification items — this is the highest-stakes reasoning skill in the module and should be the plurality of the exam, not a minority |
| **Critical-failure content** | **Yes.** Misclassifying a clear allocation-of-traffic fact pattern as "safe" is a critical-failure item — this is the exact real-world mistake that creates unlicensed-broker liability. Recommend at least one critical-failure item that must be answered correctly to pass, regardless of overall score. |
| Passing standard | Suggest 85%, with the critical-failure item(s) mandatory pass/fail independent of the percentage |
| Date-sensitive items | Any item testing the $75,000 BMC-84/BMC-85 financial-security figure — reverify against current FMCSA sources before publication |

## Module 03 — Trucks, Trailers, Freight & Equipment

**Objectives tested:** recognize common truck/trailer types; identify freight-to-equipment fit issues; separate gross-weight checks from axle/legal compliance; apply federal weight/size baselines (80,000 lb gross, 34,000 lb tandem, 102-inch width, 48-foot minimum semitrailer); use STOP/VERIFY/ESCALATE when facts are missing.

| Element | Specification |
|---|---|
| Item types | Multiple choice (regulatory figures), equipment-fit classification (GOOD FIT / BAD FIT / NEEDS MORE INFO / SPECIALIZED), short reasoning |
| Cognitive level | Mixed — recall for the federal figures, application for fit classification |
| Items per objective | 3–4 |
| Total target | 20–25 items |
| Scenario/practical coverage | 4–6 equipment-fit classification scenarios, similar in structure to the existing Knowledge Check Part C but with new fact patterns (not reused verbatim) |
| Critical-failure content | Recommend one critical-failure item on the illegal-axle-weight scenario pattern (legal gross weight but illegal axle distribution) — this is a genuine safety/legal hazard, not just a vocabulary gap |
| Passing standard | Suggest 80% |
| Date-sensitive items | None flagged — the core federal weight/size figures in this module were independently verified against primary regulatory sources during production per the instructor guide, and are stable federal figures (23 CFR § 658.17) unlikely to change on the same cadence as the FMCSA systems in Modules 04/06 |

## Module 04 — Carrier & Driver Onboarding

**Objectives tested:** build a carrier operational profile and driver dispatch profile distinct from the DQ file; verify carrier registration/authority via current FMCSA sources; recognize what a COI can and cannot prove; apply UCR/W-9/factoring-NOA issues without overstepping into legal interpretation; verify CDL class/endorsement compatibility; apply the current medical-certification transition rules with appropriate caution; recognize payment-redirection and identity-mismatch risk.

| Element | Specification |
|---|---|
| Item types | Multiple choice, true/false, scenario classification (DO NOT DISPATCH / NEEDS MORE INFO / STOP-VERIFY tiers) |
| Cognitive level | Mixed recall (current systems, figures) and application (scenario judgment) |
| Items per objective | 3–4 |
| Total target | 25–30 items |
| Scenario/practical coverage | 5–6 onboarding-decision scenarios |
| **Critical-failure content** | **Yes.** A hazmat-endorsement-mismatch item (driver lacks required H/X endorsement) should be critical-failure — dispatching that load is a direct safety/legal violation, not a judgment call. |
| Passing standard | Suggest 85%, with the critical-failure item(s) mandatory |
| **Date-sensitive items — HIGH PRIORITY** | Any item testing the NRII paper-MEC exemption (effective April 11–October 11, 2026, allows reliance on paper MECs up to 60 days) **must be reverified against current FMCSA procedure before this exam is authored**, not just before publication — the exemption expires October 11, 2026, which may occur before this exam is built. Items on Legacy L&I vs. Motus (current as of May 14, 2026) also need reconfirmation. The $750,000 BIPD floor is more stable but should still be spot-checked. |

## Module 05 — Load Boards & Freight Sourcing

**Objectives tested:** distinguish load board / broker portal / private load board; distinguish spot from contract/dedicated freight; use origin/destination deadhead as a sourcing variable; distinguish FOUND from VERIFIED AVAILABLE; apply the Module 02 shipper-direct boundary in a sourcing context; screen postings for missing information and duplicate/reposted-load patterns.

| Element | Specification |
|---|---|
| Item types | Multiple choice, true/false, sourcing-screen classification (GOOD CANDIDATE / BAD FIT / NEEDS MORE INFO) |
| Cognitive level | Application-heavy — the FOUND vs. VERIFIED AVAILABLE distinction and missing-information screening are judgment skills |
| Items per objective | 3–4 |
| Total target | 25–30 items |
| Scenario/practical coverage | 6–8 sourcing-screen scenarios — this should be the largest single item category, mirroring the module's own emphasis |
| Critical-failure content | Recommend a critical-failure item on the Module 02 shipper-direct boundary (a scenario where a dispatcher's sourcing behavior crosses into general solicitation) — getting this wrong risks the same unlicensed-broker exposure flagged as critical in Module 02 |
| Passing standard | Suggest 80% |
| Date-sensitive items | Section 5 platform descriptions (DAT One, Truckstop, Trucker Path/TruckLoads, 123Loadboard) were verified current as of August 11, 2026. If the exam tests platform-specific claims (not just concepts), those items need reverification — platform features change faster than curriculum cycles per the instructor guide's own note. Concept-only items (deadhead, FCFS, FOUND vs. VERIFIED AVAILABLE) are not date-sensitive. |

## Module 06 — Broker Verification & Fraud Prevention

**Objectives tested:** explain why entity and contact verification are separate steps; use current FMCSA systems correctly; verify broker authority and financial-security status; apply the full verification workflow and risk-classification system; recognize BEC/email-domain risk patterns without performing forensic investigation; distinguish co-brokering from double brokering; interpret factor/credit signals and DNU lists correctly; verify payment paths through trusted channels; use non-accusatory professional language throughout.

| Element | Specification |
|---|---|
| Item types | Multiple choice, true/false, risk classification (drawing on the newly extracted Scenario Lab's 12 fact patterns, but with new items — do not reuse Scenario Lab items verbatim as exam items since students will have already seen them in practice) |
| Cognitive level | Application/analysis — this is the module's core skill |
| Items per objective | 3–4 |
| Total target | 25–30 items |
| Scenario/practical coverage | 8–10 risk-classification scenarios — highest scenario weighting of any module given the fraud-prevention stakes |
| **Critical-failure content** | **Yes, and this is the highest-stakes critical-failure module in the set.** Two candidate critical-failure items: (1) a payment-redirection scenario where the correct answer is HOLD/VERIFY through a trusted channel — getting this wrong models the exact behavior that enables real financial fraud; (2) a scenario testing whether the student independently declares "fraud" from inconclusive facts — per the instructor guide's own explicit rule that no scenario should conclude with an unsupported fraud determination, a student who does this should not pass regardless of other performance. |
| Passing standard | Suggest 90% given the fraud-prevention stakes, with both critical-failure items mandatory |
| **Date-sensitive items — HIGH PRIORITY** | Motus/SAFER/Legacy L&I items (flagged by the instructor guide itself as "an active modernization area"), and BMC-85 trustee-eligibility items (January 16, 2026 rule, 30-day cure window, distinct from the separate 7-day shortfall rule) both need reverification against current FMCSA and primary regulatory sources before this exam is authored, not just before publication — the source material explicitly says this environment "is still evolving." |

## Cross-module notes

- **Remediation linkage:** for every module, a failed exam should route the student back to the specific manual section(s) tied to the missed objective, not just "retake the exam." The instructor answer guides already cite section numbers per question — that citation pattern should carry into the exam item bank so remediation routing can be automated later.
- **Do not reuse Knowledge Check items verbatim as exam items.** Students will have already seen the Knowledge Check questions; the graded exam needs materially different scenarios/wording testing the same objectives, or the exam measures memorization rather than competence.
- **Modules 04 and 06 need their date-sensitive reverification done *before* item-writing begins**, not deferred to a pre-publication gate, because both involve rules with concrete 2026 expiration/effective dates that could lapse during the writing process itself.
