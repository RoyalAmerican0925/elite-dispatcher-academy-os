## Instructional spine
**PARTIES → FOUR FLOWS → DOCUMENT PURPOSE → KNOWN / UNKNOWN / VERIFY → STOP → IDENTIFY → TRACE → VERIFY → HAND OFF → NEXT SAFE ACTION**

Every major lesson, tool, assessment and simulation decision should reinforce this same mental model.

## Instructor demonstrations

### Demonstration A — same freight, different flows
Show a delivered shipment whose POD has not reached billing. Ask what is complete and what is not. Expected insight: physical flow can be complete while document/payment flows remain open.

### Demonstration B — populated does not mean verified
Show two pickup messages with conflicting times. The correct move is not to pick the newest-looking value silently. Instructor models: identify conflict → record VERIFY → determine source/channel → reconcile → preserve change history.

### Demonstration C — M01 handoff discipline
Show a 44,000-lb van load with no detailed equipment/axle information. M01 student should identify that equipment/weight fit matters and route it to M03; they should not invent an axle/legal-fit conclusion.

## Misconceptions to correct
- “Broker moved the load.” → broker arranged; carrier/driver transported in the standard brokered scenario.
- “Shipper means owner.” → shipper role is defined by tendering/sending freight in the movement, not a universal ownership rule.
- “Rate confirmation means the load is paid.” → document/commercial state is different from payment state.
- “If both cities are in one state, it is automatically intrastate for every purpose.” → insufficient as a categorical rule.
- “Blank means none/zero.” → blank is UNKNOWN until evidence establishes otherwise.
- “The field is filled in, so it is verified.” → present information may still require verification.
- “Dispatcher can answer every trucking question.” → M01 identifies later specialized workflows.

## Tool controls
### Freight Role Map
Use to identify parties, functions and relationships without ownership assumptions.

### Load Lifecycle Sequencing Worksheet
Use to separate physical movement from communication, document and payment events.

### Dispatch File Intake & Verification Map
Use for evidence state, source-to-confirm, STOP framework, next-action status and later-workflow handoff.

A learner should not be considered M01-ready if they can define terms but cannot use these tools on a new freight file.

## Assessment controls
### Knowledge Check
Diagnostic only. Includes both recall and applied file triage. Misses should route remediation rather than become a final mastery claim.

### Exam
30 items; 80% / 24 correct. Includes a Freight File Decision Desk section. Date-sensitive FMCSA terminology must be reverified before commercial release.

### Practical
30-point Freight Movement Desk. Pass 24/30 plus completion of assumption-control remediation where required.

### Assumption-control rule
M01 does not use an automatic critical-failure family. However, repeated unsafe assumptions block competency recording until corrected on materially different facts. First-attempt evidence must remain visible.

## SIM-001 controls
SIM-001 should measure the same M01 mental model, not become a trivia game. Required evidence must include:
- party/function recognition;
- physical/information/document/payment distinctions;
- document purpose/status;
- known/unknown/verify discipline;
- STOP framework or equivalent next-action discipline;
- later-workflow handoff;
- professional reasoning on beginner misconceptions.

Do not rebuild SIM-001 solely because curriculum expanded. Add or repair only evidence that is actually missing.

## Source/currentness controls
Before commercial release, reverify authoritative/current claims relating to:
- DOT/FMCSA relationship wording;
- USDOT versus operating-authority terminology and current registration display/practice;
- interstate/intrastate statements;
- private/for-hire applicability claims.

Do not present fictional workflow examples as universal regulatory rules.
