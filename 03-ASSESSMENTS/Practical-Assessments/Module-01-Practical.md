# Module 01 Practical Assessment — Freight Movement Desk

**Status:** PREMIUM GRADED PRACTICAL — release QA remains separate  
**Type:** Integrated occupational scenario  
**Module:** 01 — Trucking Industry Foundations  
**Instructor scoring:** `03-ASSESSMENTS/Practical-Assessments/Module-01-Instructor-Scoring-Guide.md`  
**Passing standard:** 24/30 and completion of any required remediation for assumption/verification failures.

## Purpose
This practical tests whether the learner can read a basic freight file as an operating picture rather than as a list of definitions.

The learner must use the Module 01 mental model:

**PARTIES → FOUR FLOWS → DOCUMENT PURPOSE → KNOWN / UNKNOWN / VERIFY → STOP → IDENTIFY → TRACE → VERIFY → HAND OFF → NEXT SAFE ACTION**

The learner is not expected to perform advanced legal, equipment, onboarding, fraud, profitability, booking, routing or HOS analysis. The learner must recognize when those questions exist and route them correctly.

---

# Scenario — Blue River Foods / Prairie Freight Brokers / North Star Transport

Blue River Foods manufactures shelf-stable food products in Omaha, Nebraska. It is shipping a truckload to a regional grocery distribution center in Des Moines, Iowa.

Blue River contacts Prairie Freight Brokers to arrange transportation. Prairie offers the shipment to North Star Transport, an authorized motor carrier. North Star's carrier-side dispatcher is reviewing the opportunity for North Star.

### Intake record received by the dispatcher

- Carrier: **North Star Transport**
- Driver/truck: **Driver Morgan / Unit 214**
- Truck location: **Council Bluffs, Iowa, empty at 06:15**
- Equipment shown in carrier record: **53' dry van**
- Origin city: **Omaha, Nebraska**
- Destination city: **Des Moines, Iowa**
- Commodity: **shelf-stable packaged food products**
- Stated weight: **39,500 lb**
- Broker email: **Pickup FCFS 08:00–13:00 today**
- Copied internal dispatch note from yesterday: **Pickup appointment 10:30**
- Delivery message: **“tomorrow morning”** — no exact appointment/window shown
- Stated offer: **$1,300**
- Rate confirmation: **not yet issued**
- Exact pickup facility: **present in broker email**
- Exact delivery facility: **present in broker email**
- Special instructions: **not shown in the intake record**
- Broker contact: **Jordan Lee at Prairie Freight Brokers**
- Carrier billing note: North Star uses a factoring company for some eligible receivables after delivery and document completion.

### Later event
Before the student finishes the file, a second broker message arrives:

> “Correction: pickup is FCFS 08:00–13:00. The 10:30 time was copied from an earlier draft. Delivery appointment is 09:00 tomorrow. Rate confirmation will follow if North Star and Prairie complete the applicable booking process.”

The student must preserve the fact that the earlier file contained a contradiction and document how it was resolved rather than pretending the contradiction never existed.

# Student Tasks

## Task 1 — Identify the parties and functions
Identify:
- shipper;
- broker;
- motor carrier;
- dispatcher;
- driver;
- consignee/receiver;
- factoring-company role.

For each, state the function performed in this scenario. Do not use ownership assumptions as the reason for assigning shipper/consignee roles.

## Task 2 — Trace the four flows
Create a four-flow map for:
1. **Physical freight**
2. **Information / communication**
3. **Documents**
4. **Payment / receivables**

For each flow, state:
- what has already happened;
- what is currently pending;
- what would happen next if the opportunity advances.

## Task 3 — Read the documents correctly
Explain the foundation-level purpose/status of:
- broker email/message;
- rate confirmation;
- BOL;
- POD;
- invoice.

State which of these are actually present now and which are later/pending. Do not treat document presence as proof that every field is verified or that payment has occurred.

## Task 4 — Classify the intake evidence
Use **KNOWN / UNKNOWN / VERIFY** for at least these fields:
- carrier;
- driver/truck;
- truck location;
- equipment type;
- commodity;
- origin facility;
- destination facility;
- pickup timing before the correction;
- delivery timing before the correction;
- stated weight;
- stated rate;
- special instructions;
- broker contact role;
- rate-confirmation status.

For every VERIFY or UNKNOWN item, state what evidence/source would move the field forward.

## Task 5 — Apply STOP → IDENTIFY → TRACE → VERIFY → HAND OFF
Write the student's action at each step **before the later broker correction arrives**.

The answer must show why the dispatcher should not silently choose between FCFS 08:00–13:00 and 10:30.

## Task 6 — Process the changed evidence
After the broker's correction arrives:
- identify what changed;
- identify what is now resolved;
- identify what remains unresolved;
- update the file status without erasing the original contradiction;
- state the next safe action.

## Task 7 — Route specialized questions
Identify at least four questions that belong to later modules and route each correctly. Examples may include:
- legal/agency boundary;
- equipment/weight fit;
- onboarding readiness;
- broker/contact verification;
- profitability;
- negotiation;
- formal booking/rate-confirmation review;
- routing/trip feasibility;
- HOS/ELD feasibility.

Do **not** perform the advanced analysis; identify and hand off the question.

## Task 8 — Professional next-action record
Using the Dispatch File Intake & Verification Map, record one of these current statuses:
- Information gathering
- Verification required
- Ready for next applicable specialized analysis
- Hand off / escalate

Then write a concise professional case note containing:
- verified/known operating picture;
- unresolved items;
- resolved contradiction/history;
- next action;
- later-workflow owner/handoff.

# Required Deliverables
1. Completed Freight Role Map.
2. Completed Load Lifecycle Sequencing Worksheet or equivalent four-flow trace.
3. Completed Dispatch File Intake & Verification Map.
4. Written responses for Tasks 1–8.
5. Final professional case note.

# Assessment Rules
- A blank field is not permission to guess.
- A populated field is not automatically verified.
- The learner may not receive credit for a correct final answer if the written reasoning shows that the correct result was reached by an unsafe assumption.
- First-attempt evidence must be preserved before remediation.
- Retesting after a material assumption/verification failure must use a different fictional freight file.

No M01-specific automatic critical-failure family is designated. M01 is a foundation module; however, repeated unsafe assumption behavior blocks competency recording until remediated.
