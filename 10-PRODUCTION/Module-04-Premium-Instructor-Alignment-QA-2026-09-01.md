## 2. Strong occupational spine already present
Module 04 is not merely a list of onboarding documents. The current manual repeatedly requires the learner to distinguish:
- carrier compliance responsibility from dispatcher operational readiness;
- document presence from verified status;
- current/authoritative evidence from carrier-supplied representations;
- legal/regulatory requirement from industry practice and carrier policy;
- dispatch profile from DQ/compliance administration;
- payment-change request from authenticated authorization;
- discrepancy/red flag from proof of fraud;
- known current facts from time-sensitive procedures requiring reverification.

The manual includes a substantial scenario set and a diagnostic knowledge check. The practical requires an integrated onboarding-file review rather than isolated recall.

## 3. Tool chain verified
The Module 04 tool directory contains five distinct operational tools:
1. Carrier Onboarding Checklist.
2. Driver Dispatch Profile Template.
3. Equipment Profile Template.
4. Expiration & Reverification Tracker.
5. Payment-Change STOP-VERIFY-ESCALATE Tool.

These support the module's actual employment outcome and are not decorative worksheets.

## 4. Assessment alignment verified
The current practical requires the student to:
- build an onboarding decision table;
- reconcile W-9/entity information without unsupported fraud accusations;
- explain COI evidence limits;
- handle the current NRII paper-MEC scenario cautiously;
- reject the stated driver/load endorsement mismatch;
- stop an unverified payment redirect;
- maintain the DQ/compliance boundary;
- issue a final readiness/hold/do-not-dispatch decision.

The practical scoring guide uses 21 points with a 17/21 passing standard and three explicit critical-failure concepts. The exam separately requires 23/26 and Critical Item 22 correct.

## 6. Premium-depth judgment
At the current content level, Module 04 demonstrates meaningful occupational value beyond a first-page web summary because the learner must reconcile conflicting records, choose verification paths, protect sensitive/payment workflows, distinguish scope/authority, use operational tools and make integrated readiness decisions.

That supports an **instructor-alignment PASS** and allows SIM-004 architecture/design to proceed.

It does **not** eliminate the Academy-wide stronger premium-depth re-audit. During that later gate, Module 04 should still be tested against competitor depth, final rendered usability, completeness of demonstrations/artifacts, and cross-module continuity.

## 7. SIM-004 design constraints now locked
SIM-004 must be based on the existing Module 04 instructional and assessment spine. It must not invent a new curriculum.

Required competency families:
- carrier identity/registration/authority source selection;
- insurance/COI evidence limits;
- W-9/entity reconciliation;
- dispatch profile versus DQ/compliance boundary;
- CDL/endorsement compatibility;
- current medical-certification verification;
- payment/factoring change verification;
- equipment/driver/profile completeness;
- expiration/currentness tracking;
- carrier preference versus law;
- communication/decision-authority routing;
- final onboarding disposition.

Initial critical concepts remain synchronized to the practical:
1. stated required driver qualification/endorsement conflict;
2. unverified payment redirect;
3. silent assumption of carrier compliance-program authority.

## 8. Current-source risk
Module 04 contains unusually time-sensitive 2026 material. The existing manual itself flags the current FMCSA registration modernization and NRII temporary exemption for reverification.

Therefore SIM-004 must isolate date-sensitive content so it can be updated without rewriting the entire simulation. Do not hard-code a temporary 2026 rule into generic remediation language as though it were permanent.
