# Elite Dispatcher Academy — Controlled Purge Design

**Status:** APPROVED — EXECUTION AUTHORIZED  
**Date:** 2026-09-04  
**Target branch:** `academy-master-architecture`

## Purpose
Remove stale, duplicate, superseded, placeholder, and subpar material from the active Academy production path while preserving useful historical evidence and upgrading valuable instructional material rather than discarding it blindly.

## Governing standard
The active course must meet the approved premium Academy framework. File existence is not evidence of quality. Active material must contribute materially to professional dispatcher competency and fit the dependency chain:

**TEACH → DEMONSTRATE → PRACTICE → ASSESS → SIMULATE → RECORD COMPETENCY**

Active instructional material must pass the Academy premium-depth tests: it must provide more value than first-page generic search results, produce an employable operational capability, and feel like professional paid training rather than assembled free information.

## Purge classification
Every reviewed item receives one disposition:

1. **KEEP — ACTIVE:** current, aligned, and worthy of the live production tree.
2. **UPGRADE — ACTIVE:** contains valuable material but requires repair before it can satisfy the premium standard.
3. **ARCHIVE — HISTORICAL:** stale as a live control but useful as audit/history evidence; remove from live-control authority and preserve under a clearly deprecated/archive path where practical.
4. **DELETE — SUPERSEDED/JUNK:** duplicate, abandoned, empty/placeholder, misleading, or inferior content with no remaining production/history value.

## Execution rules
- Do not delete valuable source evidence merely because it is old; classify whether it remains historically or legally useful.
- Do not keep a weak lesson merely because effort was previously spent on it.
- Do not allow stale dashboards/audits to override newer verified master truth.
- Correct stale status language where actual assets now exist.
- Preserve `PUBLICATION_READY` as a separate gate from content/build completion.
- Keep release-layer browser/device/LMS/accessibility work separate from core content completion.
- No merge to `main` under this purge authorization.
- New permanent course decisions developed in chat must be transferred to the proper GitHub production/master/module folder.

## Initial execution sequence
1. Lock this design and create an implementation plan.
2. Inventory active master/production controls for stale authority conflicts.
3. Inventory M01–M08 live instructional assets for subpar/superseded duplicates and known stale metadata.
4. Inventory simulations and status controls for false/stale claims.
5. Archive/delete only after exact-file review.
6. Upgrade master truth controls and completion percentages after cleanup.
7. Verify live tree and report exact dispositions.

## Safety against destructive mistakes
No file is deleted solely from filename, age, or a prior audit label. Exact content is reviewed before destructive action. Where historical value exists, archive rather than delete. Git history remains available, but the live production tree must not force instructors/build agents to sort through obsolete truth claims.
