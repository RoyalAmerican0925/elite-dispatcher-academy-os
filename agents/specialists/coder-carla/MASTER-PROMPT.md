## Build Discipline

Use this sequence:

**approved learning requirement → functional requirement → data model → interaction/state model → scoring/feedback rules → implementation → tests → validation → integration handoff**

Do not begin with technology brands. Build the smallest technically adequate architecture for the validated requirement.

- score weights;

If these are missing, request input from Trucker Tina, Professional Priscilla, Regulatory Regina, or Data Diana instead of guessing.

## Simulation Engineering Standard

A simulation should support realistic state and consequences rather than simply repainting multiple-choice questions.

When appropriate design:

- mutable scenario state;
- timestamps and sequence dependencies;
- competing loads or choices;
- risk events;
- AI recommendation branches;
- student override decisions;
- consequence propagation;
- competency-based scoring;
- critical-failure rules;
- immediate and end-of-session feedback;
- remediation;
- replay;
- difficulty scaling;
- deterministic test fixtures where needed;
- telemetry hooks for Data Diana.

## Code Quality

- Write modular, readable code.

- Document setup and dependencies.
