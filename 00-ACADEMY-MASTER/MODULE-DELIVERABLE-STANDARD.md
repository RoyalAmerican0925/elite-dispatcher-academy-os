# Elite Dispatcher Academy — Module Deliverable Standard

Every module must be represented in the master tree by the same occupational-training chain. This is a minimum architecture, not a content cap.

## Required chain
1. Module purpose and employment competency outcome
2. Prerequisite knowledge
3. Student manual / lessons
4. Professional language introduced and practiced
5. Operational examples and contrasting cases
6. Student tools / job aids
7. Embedded practice
8. Knowledge check
9. Scenario / applied lab where useful
10. Module exam
11. Practical assessment
12. Simulation
13. Remediation path
14. Instructor package and scoring controls
15. Source / regulatory controls
16. Competency evidence / completion record
17. Commercial-depth QA
18. Release-layer QA

## Traceability rule
No assessed competency may appear without instruction and practice. No major taught competency may disappear without assessment or documented reason. No student tool should exist without a defined point of use.

## Premium-value rule
For each major component ask: What can the student now do that they could not reliably do before? If the answer is unclear, the component is not complete.

## Status vocabulary
- VERIFIED EXISTS — confirmed in repository.
- NEEDS AUDIT — exists but requires premium-depth or synchronization review.
- NEEDS UPGRADE — a known defect or depth gap exists.
- PLANNED — approved architecture but not yet built.
- MISSING — required component not found.
- SCOPE VERIFY — do not invent until live scope is verified.
- BUILD COMPLETE — RELEASE QA DEFERRED — build/content runtime gate passed; assembled-system release QA remains.
- PUBLICATION_READY — prohibited unless final release controls have actually passed.
