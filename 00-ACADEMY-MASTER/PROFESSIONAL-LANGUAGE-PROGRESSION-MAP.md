# Professional Language Progression Map

Professional fluency is a taught, practiced and assessed Academy competency. Terms are introduced when the student has enough context to understand them and then reused in later work.

| Stage | Language focus | Student performance |
|---|---|---|
| Module 01 | freight ecosystem, roles, lifecycle, basic documents and operating terms | identify and use foundational terms correctly |
| Module 02 | agency, broker/dispatcher boundaries, authority and escalation | describe roles without overclaiming legal status |
| Module 03 | equipment, dimensions, weight, axle and qualification language | communicate load-fit facts precisely |
| Module 04 | onboarding, insurance, tax/identity, driver and payment-document language | document missing/conflicting onboarding information professionally |
| Module 05 | load boards, sourcing, screening, availability and opportunity language | conduct and document a professional opportunity screen |
| Module 06 | entity/contact/load/payment verification, fraud indicators, impersonation and evidence language | communicate red flags as indicators/evidence, not unsupported accusations |
| Module 07 | rates, loaded/effective RPM, costs, contribution margin, break-even and positioning language | explain economic comparisons in carrier-usable language |
| Module 08 | negotiation, counteroffer, target/floor, leverage, concession, rate request and broker communication | conduct a professional rate discussion and document the result without bluffing about facts |
| Module 09 | booking, rate confirmation, terms, instructions, reference numbers, discrepancies and dispatch documentation | confirm what was agreed, identify document conflicts and communicate booking status precisely |
| Module 10 | route, ETA, appointment/window, transit time, fuel stop, mileage, buffer and feasibility language | communicate a trip plan using explicit assumptions and operational constraints |
| Module 11 | HOS, ELD, duty status, driving window, on-duty/not-driving, off-duty, sleeper berth, break, cycle and recapture language | discuss feasibility without inventing a driver's available hours or treating a planning estimate as an ELD fact |
| Module 12 | check call, status update, arrived, loaded, departed, in transit, ETA, delay notice and communication cadence | maintain concise factual load-status communication and distinguish actual status from expectation |
| Module 13 | detention, layover, TONU, breakdown, rejected freight, OS&D/claim-related language, exception, escalation and authorization | describe exceptions factually, preserve evidence and avoid promising agreement-specific compensation without verification |
| Module 14 | POD, invoice, billing packet, factoring, notice of assignment, payment status, aging/follow-up and closeout | communicate document/payment status accurately and distinguish delivery completion from financial closeout |
| Module 15 | client service, SOP, service scope, status tracker, escalation matrix, handoff, performance report and integrated dispatch language | communicate as a professional dispatcher across the complete workflow and produce a clear shift/client handoff |

## Scope-control note for Modules 08–15
The language families above are grounded in the repository's verified program maps. They are architecture targets, not evidence that those modules have been authored. Exact definitions, examples, regulatory notes and assessment criteria must be locked during each module's production/research cycle.

## Required term lifecycle
Every high-value term should progress through:
1. **Introduce** — plain-English meaning and correct industry meaning.
2. **Contrast** — what it is not / commonly confused term.
3. **Hear/read** — realistic call, email, board, document or dispatch-note usage.
4. **Use** — student must employ it in a decision, explanation or artifact.
5. **Correct** — remediation addresses misuse.
6. **Transfer** — term reappears later in a more complex context.

## Communication quality rubric
Student language should be evaluated for:
- factual precision;
- correct role terminology;
- distinction between verified fact, assumption and unresolved information;
- distinction between law/regulation, contract/agreement term, carrier policy, platform rule and Academy teaching model;
- concise operational communication;
- no unsupported accusation or legal conclusion;
- clear next action / ownership / handoff;
- appropriate professional tone;
- correct use of time/status qualifiers;
- correct distinction between a plan/estimate and an observed/verified operating fact.

A correct conclusion expressed with materially misleading terminology is not full mastery.

## Cross-module transfer rule
Later modules must deliberately reuse earlier vocabulary under more complex conditions. Examples:
- `deadhead` begins as an operating concept in Module 01 and becomes an economic input in Module 07;
- `rate confirmation` begins as document recognition, then becomes a booking/document-review object in Module 09;
- `appointment` begins as a facility-timing concept and becomes a trip-planning constraint in Module 10;
- `verification` begins as a foundational discipline, becomes specialized fraud/risk screening in Module 06, and remains active through booking, payment changes and capstone work;
- `POD` begins as foundational document recognition and becomes a closeout/billing control in Module 14.

The Academy dictionary should show these transfers so students learn one coherent professional language rather than fifteen disconnected glossaries.
