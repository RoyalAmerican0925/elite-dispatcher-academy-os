**Classification:** NEEDS MORE INFORMATION / VERIFY.

Commodity is one of the core missing-information categories in Section 14\. Without knowing what's actually being hauled, several other checks (temperature needs, hazmat status, handling requirements) can't be completed — this needs verification before it can be evaluated further.

### S-05-05: FCFS Without Facility Hours

A posting lists delivery as FCFS but does not state the facility's operating hours.

**Classification:** NEEDS MORE INFORMATION / VERIFY.

As Section 11 explains, FCFS describes arrival order, not round-the-clock access. Without facility hours, a dispatcher can't confirm this load's delivery window actually works for the driver's schedule — this is a real gap, not a detail to assume away.

### S-05-06: Older Posting Still Visible

A posting that appears to be several hours old is still showing as active on the board.

**Classification:** VERIFY AVAILABILITY / lower priority depending on alternatives.

Per Section 15, posting age is a priority signal, not proof either way. This load should be checked lower in priority order if fresher candidates exist, but its age alone doesn't disqualify it — availability still needs direct verification before it's ruled in or out.

### S-05-07: Similar Freight Under Multiple Companies

The same-looking load (same lane, similar weight and commodity) appears posted under two different company names.

**Classification:** VERIFY / route to Module 06 screening if unresolved.

Per Section 16, this has several possible innocent explanations alongside the possibility of double brokering. The correct Module 05 response is to flag it and verify basic details — not to conclude fraud from the pattern alone. If verification doesn't resolve it cleanly, this moves to Module 06's fraud-screening process.

### S-05-08: Home-Time Conflict

The assigned driver is committed to return to Dallas by Friday. The candidate load would deliver in Seattle on Friday.

**Classification:** BAD FIT / REJECT.

This load is geographically incompatible with the driver's home-time commitment (Section 13) — Seattle to Dallas isn't achievable in the time this load would require, making the home-time conflict disqualifying regardless of the load's other merits.

### S-05-09: Hazmat Endorsement Mismatch

A posting explicitly requires placarded hazmat transport with H/X endorsement. The assigned driver does not hold H or X.

**Classification:** BAD FIT / DO NOT PURSUE for that driver.

This mirrors Module 03/04's endorsement-qualification logic directly: a driver without the required endorsement cannot legally haul this load. This is a hard qualification mismatch, not something to negotiate around.

### S-05-10: Ambiguous Temperature Note on a Van-Coded Load

A posting is coded as standard van equipment, but the notes field says "protect from freeze / maintain temperature."

**Classification:** NEEDS MORE INFORMATION / VERIFY EQUIPMENT REQUIREMENT.

The equipment code and the notes field conflict — this needs clarification before assuming either one is correct. Don't automatically assume reefer equipment is required either; the freeze-protection need might be addressable in other ways depending on the actual commodity and conditions. Verify what's actually needed before ruling the load in or out.

### S-05-11: Partial Freight, Weight Without Dimensions

A partial-load posting lists a weight figure but no length, width, or height information.

**Classification:** NEEDS MORE INFORMATION / VERIFY.

Per Module 03's fit-checklist logic, weight alone never confirms fit for partial freight sharing trailer space. This posting needs length × width × height, loading orientation, available space, weight distribution, and any equipment restrictions before it can be evaluated.

### S-05-12: Load Already Covered

A load looked like a strong candidate on paper. When the dispatcher calls the broker, the broker says the load was just covered by another carrier.

**Classification:** UNAVAILABLE.

This is the clearest possible illustration of Section 17's core lesson: FOUND does not equal AVAILABLE. No amount of paper-based evaluation substitutes for direct confirmation — this load is simply gone, and the dispatcher moves on to the next candidate.
